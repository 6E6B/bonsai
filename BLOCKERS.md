# Blockers

Things that can't be finished from inside this environment, and what was done instead.

| # | Blocker | Workaround | Needed to close |
|---|---------|------------|-----------------|
| 1 | Only one test account (cookie) is available. | The Phase 2 exit flow (three accounts, switch in one frame from cache, launch as each) is covered by UI tests with three synthetic accounts and replay fixtures; sign-in, switching and search were also checked live in a real window with the one account. | Two more test cookies, then run the flow by hand. |
| 2 | The test account has no friends. | Friends and presence fixtures are synthetic, built from public users 1 (Roblox) and 156 (builderman) and a real Crossroads server id. | A test account with friends who are in a game. |
| 3 | No Roblox player is installed in the sandbox (Linux). | Launch is checked up to the `roblox-player:` URI via `RecordingOpener`; the ticket mint is checked live. | Run Join on Windows or macOS with the player installed. |
| 4 | No Secret Service in the sandbox. | Cookies stay in memory; restart shows "Cookie missing from the keychain". Keychain code paths are covered by unit tests with `MemoryCookies`. | Run on a desktop with a keychain. |
| 5 | Buying can't be run live: the test account has 0 Robux and a real purchase spends Robux. The request shapes were read from the site's ItemPurchase bundle on 2026-10-14 (passes: `game-passes/v1/game-passes/{productId}/purchase` with the pass's productId, which is why the 2026-10-12 probe with the pass id failed; items: `marketplace-sales/v1/item/{id}/purchase-item` and `purchase-resale`). | Passes, items, bundles and resale copies are bought in-app behind a confirm that shows price and balance (`purchase.rs`). Sale details (`marketplace-items/v1/items/details`) are recorded live; purchase responses in `purchases.json` are synthetic. "Open on website" still works. | Buy one cheap pass and one cheap item with an account that has Robux, recording with `RBX_RECORD=1`, and replace the synthetic responses. |
| 6 | Private server buy and configure can't be run live: the test account owns none and buying (even a free one) would create one. | Synthetic fixture `experience_actions.json` from the tracker swagger; the buy asks first (price shown, free ones too). | An account that owns a private server. |
| 7 | Sending private messages: `POST privatemessages.roblox.com/v1/messages/send` answers 404 (2026-10-13, valid-shaped body) and is gone from the tracker, though the site's PrivateMessage bundle still references it. | Reply and Compose will start a chat (platform-chat-api) instead. | Recheck if Roblox brings it back. |
| 8 | Trades can't be exercised live: the test account has no limiteds and trading would involve real people. | Synthetic fixture `trades.json` from the tracker's trades v1/v2 schemas; every write asks first and shows both sides and the net. | An account with limiteds and a second consenting account to trade with. |
| 9 | Chat, forums, membership and the community admin views can't be recorded live: no test cookie in this environment, the test account has no conversations or admin role, and writes would reach real people. | Request shapes from the site's bundles (ReactChat, GroupForums, GroupDetails); synthetic fixtures `chat.json` and `communities.json`. Public community calls are recorded live and signed out (`communities_public.json`). | A test account that admins a test community and has a consenting friend to chat with; then record with `RBX_RECORD=1`. |
| 10 | Sent friend requests: no endpoint to list or cancel outgoing requests is in the tracker or `specs/undocumented/`, and it can't be captured here (no browser session). | Profiles show "Request sent" from the relation; the Requests tab lists incoming only. | Capture the profile page's Cancel Request call and the requests page's sent tab in devtools, add the spec and a fixture. |
| 11 | A user's created models, decals, audio and dev assets: no listed endpoint returns another user's creations by asset type. | The Creations tab lists their public experiences. | Capture the call the profile's Creations tab makes, add the spec and a fixture. |
| 12 | 3D full-body avatar: needs the `avatar-3d` JSON plus mesh and texture downloads from the CDN (none captured) and a WebGL renderer. | The About tab shows the 2D full-body render (`thumb://avatar`) beside what they wear. | Capture the 3D thumbnail flow and agree on a renderer dependency. |
| 13 | Payouts, recurring splits and ally/enemy requests can't be run live: they move Robux or reach other communities. | Request shapes from the tracker's groups v1 schemas; synthetic responses in `communities.json`; every write asks first. | An account that owns a test community with funds. |
| 14 | Sales, stipends and community ledgers can't be recorded live: the test account has no sales, no Premium and no community funds. Whether a Sale amount is already net of the marketplace fee is unverified. | User totals, type flags, purchases and paging are recorded live (`transactions.json`, scrubbed). Sales, stipends, pending release and the community summary and ledger are synthetic (`transactions_ledger.json`) in the live shapes. No fee split is shown. | An account with a sale (ideally one still pending), Premium, and a community whose funds it may see; then record with `RBX_RECORD=1`. |
| 16 | Deleting a chat or private message: no delete endpoint is in the tracker, `specs/undocumented/` or the site's ReactChat and PrivateMessage bundles (checked 2026-10-15). | Messages can be archived; chat messages can't be removed. Dropped from the plan. | Capture a delete call if Roblox adds one. |
| 17 | Marking a single notification read: `POST notifications.roblox.com/v2/stream-notifications/mark-interacted` answers 404 (2026-10-15), and the site's notification stream only marks all read. | "Mark all read" only. Dropped from the plan. | Capture a per-entry call if Roblox adds one. |
